# Current state — the long form

`CLAUDE.md` carries a one-line index of what has landed. This file carries the long form:
what each area actually consists of, in the detail that used to live in `CLAUDE.md`'s
"What has landed" table.

**This is not where reasoning lives.** The "why" is in the per-area decision records
listed in `CLAUDE.md`'s *Authoritative documents* table. This file is the middle layer —
more than an index, less than a decision record. Read it when the index line is not enough
to tell you what you are touching; read the decision record when you need to know why it
is that way.

Why the split: `CLAUDE.md` loads into every session *and every subagent*, so length there
is a tax paid on every task, including tasks that never touch the area described. This
file is read on demand. The same discipline applies here that applied there — when a later
change supersedes an earlier one, **rewrite the row rather than appending the new story
beneath the old one.**

### Why `npm audit fix --force` is banned here

`CLAUDE.md` states the rule; this is the reasoning behind it.

Its only remaining suggestion is `drizzle-kit@0.18.1` — a major **downgrade** of the tool
that generates migrations against the live database. The four residual moderate advisories
it is offering to "fix" are all one chain:

```
drizzle-kit → @esbuild-kit/esm-loader → @esbuild-kit/core-utils → esbuild@0.18.20
```

Nothing forward fixes it: drizzle-kit is already at latest and still declares the
deprecated loader. And it is **not reachable** — drizzle-kit's shipped JS contains no
reference to `@esbuild-kit` at all, and the advisory concerns esbuild's dev *server*,
which `core-utils` never starts (it calls `transform`/`transformSync` only).

Plain `npm audit fix` is fine, and is what cleared the rest.
